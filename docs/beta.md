# SIAMS Frontend: Implementation Guide
### What you build, with what, in which order, under which rules

> Audience: the developer building the screens. The foundation (`setup-frontend.sh`) already gives you the API layer, auth, routing, caching, form schemas, tests and CI. **You build: the shared UI components, every page, and the landing page.** This guide lists each piece, the exact modules to import, the business rules to respect and the tests to write.
> Companion documents: `docs/frontend-design.md` (architecture), `docs/internship-system-design.md` (system), `docs/CONTRACTS.md` (team contracts).

## 2. Rules (read once, follow always)

### 2.1 Architecture rules (ESLint enforces most of them)

1. **Never import `axios`** outside `src/lib/api`. Use the feature hooks.
2. **Never write an API path in a component.** Paths live in `features/*/api.ts` only.
3. **Never write a route path string.** Use `ROUTES.x` and `to.x(id)` from `@/config/routes`.
4. **Pages import hooks from the feature**, and other features only through their index: `import { useOrganizations } from '@/features/organizations'`. Deep imports across features (`@/features/organizations/api`) are lint errors.
5. **`components/shared/*` never imports a feature.** Shared components receive data and callbacks through props.
6. **`lib/*` never imports components or features.**
7. **No `dangerouslySetInnerHTML`.** User text (notices, feedback, activities) renders as plain text with `whitespace-pre-wrap`.
8. **No tokens or user data in `localStorage` / `sessionStorage`.**
9. **No new dependency without a reason in the PR description.**

### 2.2 Data rules

| Rule | Detail |
|---|---|
| Server data is read **only** through hooks | Never `useEffect` + fetch |
| After a write, **do nothing about the cache by hand** | Each mutation hook already invalidates what it must (`invalidate:` in `hooks.ts`) |
| No optimistic updates for workflow steps (submit, approve, return, finalize) | Show the pending state, then show what the server says |
| Screens with an open form pass `refetchOnWindowFocus: false` to the entry query | So a background refetch never overwrites typing (`useLogbookEntry(id, { refetchOnWindowFocus: false })`) |
| Filters, page, sort and tab live **in the URL** | Refresh, back/forward and sharing must work (`useUrlState`, 4.2) |
| Decimals arrive as strings | Always `toNumber()` / `formatHours()` / `formatPercent()` from `@/lib/format` |
| Date-only values (`2026-11-09`) | Show with `formatDate()`, send with `toDateOnly(date)`. Never `new Date('2026-11-09')` |
| Datetimes | Show with `formatDateTime()` (Nairobi time, 24 h). Send ISO strings |
| Weeks start Monday | Week picker offers only Mondays inside the placement dates (`mondayOf`, `isMonday`) |

### 2.3 UX rules

1. **Every query result has three states** handled by shared components: loading (`LoadingState`/skeleton), empty (`EmptyState`), error (`ErrorState` with a retry button). No page renders `undefined`.
2. **A 404 on a detail page means "not found or not yours"**: show the same `NotFound` message, no hint.
3. **Submit buttons** are disabled while `mutation.isPending`.
4. **Destructive or irreversible actions** (reject, terminate, finalize, archive, delete image, reopen week) go through `ConfirmDialog`.
5. **Errors**: field errors under the field (`applyApiErrors`), everything else in an `Alert` or a toast. The wording always comes from the server's `message`.
6. **Status is never conveyed by colour alone**: use `StatusBadge` (icon + text + fill style).
7. **Keyboard**: every interactive element reachable and operable; dialogs trap focus (shadcn does this, do not break it).
8. **Role-aware UI is a convenience**: hide controls with `can(user, 'action')`, but always handle the server's 403/404.

### 2.4 Visual rules

Black and white. Inter. 14 px application text (`text-sm`), 16 px for landing body and mobile inputs. Use only the semantic tokens (`bg-background`, `text-muted-foreground`, `border`, `bg-primary`…), never raw colours. The only hue is `destructive`. Details in `docs/frontend-design.md` section 10.

### 4.2 `useUrlState` (🔨 `src/lib/use-url-state.ts`)

```ts
// Reads and writes page, page_size, search, ordering and arbitrary filters in the query string.
export function useUrlState<T extends Record<string, string | number | undefined>>(defaults: T): {
  state: T;                                 // parsed from the URL, numbers coerced for page/page_size
  set: (patch: Partial<T>) => void;         // merges, resets page to 1 when a filter changes
  reset: () => void;
};
```

- Built on React Router `useSearchParams` (`replace: true` for filter typing, `push` for page changes).
- Omit keys equal to their default so URLs stay short.
- `DataTable` + `FilterBar` read/write through it; the page passes `state` straight into the list hook (`usePlacements(state)`).
- Unit-test: defaults omitted, `page` resets on filter change, invalid numbers fall back.

## 5. Recipes (copy, adapt, keep the structure)

### 5.1 A page with data

```tsx
// src/features/placements/pages/placements-page.tsx
import { PageHeader } from '@/components/shared/page-header';
import { DataTable } from '@/components/shared/data-table';
import { FilterBar } from '@/components/shared/filter-bar';
import { usePlacements } from '../hooks';
import { useUrlState } from '@/lib/use-url-state';
import { to } from '@/config/routes';

export default function PlacementsPage() {
  const { state, set } = useUrlState({ page: 1, search: '', status: '' });
  const query = usePlacements({ ...state, status: state.status || undefined });
  return (
    <>
      <PageHeader title="Placements" description="Review and approve placement requests." />
      <FilterBar /* search + status select, writes to the URL */ />
      <DataTable
        columns={columns /* student, organisation, period, status via StatusBadge, submitted_at */}
        data={query.data}
        isLoading={query.isPending}
        error={query.error}
        state={state}
        onStateChange={set}
        rowHref={(row) => to.placementDetail(row.id)}
      />
    </>
  );
}
```

### 5.2 A form with a mutation (every form looks like this)

```tsx
const form = useForm<PlacementDraftValues>({
  resolver: zodResolver(placementDraftSchema),
  defaultValues,
});
const save = useCreatePlacement();
const [formErrors, setFormErrors] = useState<string[]>([]);

const onSubmit = form.handleSubmit(async (values) => {
  setFormErrors([]);
  try {
    await save.mutateAsync(values);
    toast.success('Draft saved');
  } catch (error) {
    // field errors land on the fields; the rest is returned for an Alert
    setFormErrors(applyApiErrors(form.setError, error, Object.keys(values)).formErrors);
  }
});
// <form onSubmit={onSubmit}> ... <ApiErrorAlert messages={formErrors} /> <Button disabled={save.isPending}>Save</Button>
```

- Schemas using `z.coerce` (logbook, periods, users): type the form as `useForm<z.input<typeof schema>, unknown, z.output<typeof schema>>`.
- Import the toast as `import { toast } from 'sonner'`.
- Business-rule failures (422/409) are not field errors: `applyApiErrors` returns them in `formErrors`; show them in `ApiErrorAlert` (it renders `details.missing` checklists).

### 5.3 Handling a 409 "state changed under you"

```tsx
try { await approve.mutateAsync({ id, body }); }
catch (error) {
  if (hasStatus(error, 409)) { toast.error(errorMessage(error)); void query.refetch(); } // show the true state
  else throw error;
}
```

### 5.4 Role-aware controls

```tsx
const { user } = useAuth();
{can(user, 'placement:approve') && placement.status === 'SUBMITTED' && <Button onClick={openApprove}>Approve</Button>}
```

Pair every `can()` check with the status check: the permission says *who*, the status says *when*.

### 5.5 File upload (image or report)

```tsx
<FileDropzone
  accept={REPORT_ACCEPT}
  maxMb={MAX_REPORT_MB}
  validate={validateReportFile}                 // from '@/features/final-report'
  progress={progress}
  onFile={(file) => upload.mutate({ placementId, file, onProgress: setProgress })}
/>
```

Client checks are a courtesy; show the server's message when it rejects (`bad_content`, `file_too_large`, `bad_extension`).

### 5.6 Private files (images and downloads)

```tsx
<ProtectedImage imageUrl={imageFileUrl(image.id)} alt={image.caption || image.original_name} />   // from '@/features/logbook'
<DownloadButton url={report.download_url} filename={report.original_name} label="Download report" />
```

Never put an API file URL in a plain `<img src>` or `<a href>`: the Bearer header cannot be sent that way.

### 5.7 Async jobs (CSV import, export)

```tsx
const start = useStartExport();                       // POST -> 202 { job_id }
const [jobId, setJobId] = useState<string>();
const job = useExportJob(jobId);                      // polls every 2 s, stops on SUCCESS/FAILURE/5 min
useEffect(() => { if (job.data?.status === 'SUCCESS' && job.data.download_url) void downloadFile(job.data.download_url, job.data.filename); }, [job.data]);
// <JobProgress job={job.data} />   a 404 from the poll means "expired or not yours"
```

### 5.5 Testing a page (template)

```tsx
it('lets the coordinator return a placement with remarks', async () => {
  server.use(
    ...signedInHandlers(user('COORDINATOR')),
    http.get(url('/api/v1/placements/'), () => HttpResponse.json(page([placement({ status: 'SUBMITTED' })]))),
  );
  const calls = captureApi(); // or a specific handler asserting the request body
  renderWithProviders(<PlacementsPage />, { role: 'COORDINATOR', route: '/app/placements' });
  await userEvent.click(await screen.findByRole('button', { name: /return/i }));
  await userEvent.type(screen.getByLabelText(/remarks/i), 'Add a phone number.');
  await userEvent.click(screen.getByRole('button', { name: /confirm/i }));
  await waitFor(() => expect(calls.some((c) => c.path.endsWith('/return/'))).toBe(true));
});
```

Rules for page tests: query by **role and accessible name**; unhandled API requests fail the test on purpose (add a handler); assert the **request** (method, path, body) and the **visible result**; run `expectNoA11yViolations(container)` once per page.

## 6. Page-by-Page Specifications 🔨

Each page: **file** (exact name from `src/app/pages.ts`), **route**, **roles**, **imports**, **compose**, **rules**, **tests**. All hook names exist today (`✅`). Beta-backed pages are marked ⚠️: develop against MSW until the real schema lands (section 10).

### 6.1 Public pages

#### Landing page (static, no API)
- **File** `src/pages/landing/landing-page.tsx` · **Route** `/` · **Roles** anyone
- **Rule: zero network requests.** No hooks from `features/*`, no `useAuth` data reads. The test setup fails any unmocked request, so a stray call breaks the test.
- **Compose** header (`navigation-menu` + `button` "Sign in" → `ROUTES.login`, `sheet` for mobile) · hero · the five problems and how SIAMS fixes them (`card` ×5) · how it works per role (`tabs` + `card`) · feature highlights · FAQ (`accordion`) · footer. Body 16 px, headings `text-3xl`–`text-5xl`.
- **Content source** `docs/internship-system-design.md` section 1 (problem → solution table) and section 2 (features).
- **Tests** renders with no requests; axe clean; the "Sign in" link points to `/login`; keyboard reaches every link.

#### Error pages
- **Files** `src/pages/errors/not-found.tsx` (`*`), `forbidden.tsx` (`/forbidden`, where `RequireRole` redirects), `server-error.tsx` (`/error`)
- Each: title, one sentence, a button back (`ROUTES.dashboard` if signed in via `useAuth()`, else `ROUTES.landing`).
- **Rule:** the same `NotFound` text for "does not exist" and "not yours" (the API answers 404 for both).
- Optional: render `server-error` from `src/app/error-boundary.tsx` in place of the plain fallback.

#### Login
- **File** `src/features/auth/pages/login-page.tsx` · **Route** `/login`
- **Imports** `useLogin`, `loginSchema` from `@/features/auth`; `safeNext` from `@/lib/auth/redirect`; `useAuth`; `applyApiErrors`
- **Compose** `TextField` email, `TextField` password (type password, `autocomplete="current-password"`), submit button, link to `ROUTES.forgotPassword`, `ApiErrorAlert`.
- **Behaviour** on success `navigate(safeNext(searchParams.get('next')), { replace: true })`. If `useAuth().status === 'authenticated'` redirect immediately. Wrong credentials come back as `400 validation_error` with `non_field_errors`: show in the alert (do not say whether the email exists). On `429` show the server message and disable the button for `error.retryAfter` seconds.
- **Tests** success redirects to `next`; hostile `next=https://evil.example` goes to the dashboard; wrong password shows the alert and no navigation; button disabled while pending.

#### Forgot password
- **File** `src/features/auth/pages/forgot-password-page.tsx` · **Route** `/forgot-password`
- `useRequestPasswordReset`, `forgotPasswordSchema`. **Always** show the same neutral confirmation ("If this email has an account, a link was sent"), success or not, so accounts cannot be probed. Only a network/5xx error shows an error.

#### Reset / set password (also the invitation link)
- **File** `src/features/auth/pages/reset-password-page.tsx` · **Route** `/reset-password/:uid/:token`
- Emails from the backend link here: `FRONTEND_URL/reset-password/<uid>/<token>/`. Used for "forgot password" **and** for first-time passwords of invited users (students, supervisors).
- `useParams()` → `useConfirmPasswordReset().mutateAsync({ uid, token, ...values })`, `resetPasswordSchema`.
- Invalid or expired link → `validation_error` with `token`/`uid` details: show "This link has expired" with a button to `ROUTES.forgotPassword`. Success → `toast.success`, navigate to `ROUTES.login`.
- **Tests** mismatch shows error on the second field; expired link shows the recovery action.

#### Profile
- **File** `src/features/auth/pages/profile-page.tsx` · **Route** `/app/profile` · **Roles** all
- `useAuth().user`, `useUpdateMe` + `profileSchema` (name, phone), `useChangePassword` + `changePasswordSchema`. Read-only: email, role (`RoleBadge`), registration number (students), organisation (workplace supervisors). Footer shows `APP_VERSION` from `@/config/env`.

## 9. Testing Requirements

### 9.1 What every page must have

| Test | How |
|---|---|
| Renders loading, empty, error and success | `server.use(...)` handlers; assert by role/name |
| Calls the expected endpoint on each action | `captureApi()` or a handler that records `request.json()` |

### 9.2 Test utilities you have ✅

```ts
import { renderWithProviders, createHookWrapper } from '@/test/render';   // providers: QueryClient (no retries), Router, Auth (signed-in role)
import { server } from '@/test/msw/server';                               // MSW; unhandled requests FAIL the test

```

Example handler: `server.use(http.get(url('/api/v1/placements/'), () => HttpResponse.json(page([placement({ status: 'SUBMITTED' })]))))`.

### 9.3 Rules

1. Query by **role and accessible name** (`getByRole('button', { name: /approve/i })`), never CSS classes. If you cannot find an element by role, the markup is probably not accessible.
2. One behaviour per test; arrange with factories, not copied JSON.
3. Add a handler for every request the page makes: an unexpected request is a failing test on purpose.
4. Do not mock the hooks; mock the **network** (MSW). That tests the real cache and invalidation.
5. Shared components get their own tests, including keyboard use (`userEvent.tab()`, `{Enter}`, `{Escape}`).
6. Coverage thresholds apply to `src/lib` and `src/config` (70/65/60) and are already met by the foundation; keep them green.

| Final-report and export `file` path parameter | written as `{id}` / `{job_id}` | after generation `tsc` shows the exact `{name}`; fix the literal |
| `GET /placements/{id}/…` path parameter names | `{id}` for viewsets, `{placement_id}` for explicit views | same |

**How to fix a mismatch (always in this order):** correct `api.ts` → correct `types/domain.ts` → correct the MSW factory in `test/msw/data.ts` → update the contract case in `src/test/features.contract.test.ts` → run the tests.

### 10.2 Things the backend does that the UI must respect

| Backend behaviour | UI consequence |
|---|---|
| Out-of-scope data returns **404** (not 403) | One `NotFound` message |
| `POST …/submit/`, `…/approve/` on a stale state return **409 `invalid_transition`** | Toast + refetch (recipe 5.3) |
| Rule failures return **422** with `code` and `message` (some with `details.missing[]`) | `ApiErrorAlert` |
| Throttling: login 5/min, users 120/min, anonymous 20/min | Debounce searches (300 ms, min 2 chars), disable submit after 429 for `retryAfter` |
| Files are private; cloud storage answers **302** to a signed URL | Use `downloadFile` / `ProtectedImage`; the storage bucket must allow CORS `GET` from the app origin (open item with the backend team) |
| Async jobs expire after 24 h | A `404` while polling means "expired or not yours" |
| Access token lives 15 min, refresh rotates | Nothing to do: the client refreshes and retries once; two tabs are serialised |
| Invited users get an email with a link to `/reset-password/<uid>/<token>/` | The reset page must exist (P2) |

### 10.3 Report problems like this

When a call fails or a shape differs, send: the endpoint (method + path), the status and body (`{code, message, details}`), the hook or page that made the call, and a copy of the Swagger entry. That is enough to decide whether the fix belongs to the frontend or the backend.

### 12.4b Domain vocabulary (spell it like the API)

Placement: `DRAFT → SUBMITTED → APPROVED | RETURNED | REJECTED`; `RETURNED → SUBMITTED`; `APPROVED → COMPLETED | TERMINATED`. Logbook week: `DRAFT → SUBMITTED → APPROVED | RETURNED`; `RETURNED → SUBMITTED`; coordinator may reopen `APPROVED → RETURNED`. Final report: `SUBMITTED → ACCEPTED | RETURNED`. Assessment: `DRAFT → SUBMITTED` (locked). Rubric form: versioned; locked once an assessment exists. Only **approved hours** count towards the required hours.
